# Admin MFA (TOTP) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Force every CTFd admin through a TOTP second factor before any admin page or API call, as a first-party plugin.

**Architecture:** One plugin `CTF/CTFd/plugins/admin_mfa/` holds pure helpers (`totp.py`, `crypto.py`, `qr.py`), a model and migration, a `before_request` gate (`gate.py`), a blueprint with setup/verify pages (`views.py`), and a CLI reset command. CTFd core is not modified.

**Tech Stack:** Python 3.11, Flask 3.1, Flask-SQLAlchemy, Alembic (CTFd plugin migrations), `cryptography` (Fernet, HKDF; already a dependency), `qrcode==8.2` (new, plugin-local), pytest.

**Spec:** `docs/superpowers/specs/2026-11-10-admin-mfa-design.md`

## Global Constraints

- Do not modify files under `CTF/CTFd/` outside `CTF/CTFd/plugins/admin_mfa/`.
- TOTP: RFC 6238, SHA1, 6 digits, 30 s period, window ±1 step; `T = floor(unix/30)`.
- Key: env `ADMIN_MFA_ENCRYPTION_KEY` (Fernet key). Fallback is `HKDF(SHA256, length=32, salt=b"ctfd-admin-mfa-v1", info=b"ctfd-admin-mfa-encryption")` over `SECRET_KEY`, urlsafe-b64 encoded, plus one warning log.
- Issuer label: `Eclipse CTF`.
- 10 recovery codes, format `XXXXX-XXXXX`, stored as `salt_hex$sha256_hex` (16-byte salt per code); compare with `hmac.compare_digest`.
- Session flag: `session["admin_mfa_ok"] = {"uid": session["id"], "h": session.get("hash")}`; PRG key `session["_admin_mfa_codes"]`.
- Verify POST rate limit: `@ratelimit(method="POST", limit=10, interval=300)`.
- Error JSON: 401 `{"success": false, "errors": ["MFA verification required"]}`, 403 `{"success": false, "errors": ["Admin API tokens are disabled; use an MFA-verified session"]}`.
- All forms POST with CTFd `nonce` field; no inline `<script>`; QR is inline `<svg>` (no `data:` URI).
- Plugin tests must use `create_ctfd(enable_plugins=True)`; `TestingConfig` sets `SAFE_MODE=True`, which skips plugins for every other test.
- Run tests from `CTF/`: `python -m pytest tests/plugins/admin_mfa -q`.

## Review Focus

1. **Admin who is logged in, then demoted/promoted mid-session.** The gate must read the type fresh each request (`is_admin()` uses cached attrs and `clear_user_session` on change). Test: promote a player to admin while they are logged in; their next `/admin` request redirects to setup (Task 4).
2. **`next` open redirect on verify.** `next=//evil.com` or `https://evil.com` must fall back to `/admin` (Task 5).
3. **Pending (not enabled) enrolment row.** An admin who abandons setup and returns must see the **same** secret (not a new one each GET), and the verify page must not accept a pending row (Task 5).
4. **Codes with spaces / pasted `123 456`.** These must be accepted after normalization; `12345a` and 7 digits are rejected (Task 1).
5. **Encryption key changes between enrol and verify.** Verify must show a generic error and never accept the code (Task 2 + Task 5).
